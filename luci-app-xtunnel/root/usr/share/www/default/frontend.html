Frontend

The frontend is everything at the top level of the archive: the router serves these files as they are. Nothing is processed on the fly, so any static output works: hand-written HTML, the output of a generator such as Hugo or Astro, an export from a site builder.

Layout

index.html        required: the home page
404.html          optional: served for every missing address, in the site's own style
style.css         styles, images, fonts — whatever you like
app.js
img/logo.svg
about/index.html  nested pages: https://domain/about/
robots.txt
favicon.ico
.xtunnel-ddns/     optional: the backend, never served over HTTP (see "Backend")
cgi-bin/login     optional: the login page (see "Login page")

The site lives at the root of the domain, so absolute paths like /style.css work. Directory listings are switched off while a site is served: a directory without an index.html answers 403. If the site has a 404.html, the router serves it, with status 404, for every address that does not exist, including the administration addresses when nobody is logged in; without it the web server's plain "Not Found" is shown.

Everything outside .xtunnel-ddns/ is available over HTTPS to anyone, including files whose names start with a dot. Keep keys, passwords and drafts out of the archive's top level.

Names the router reserves

To keep the administration reachable, the router adds links to its own files into the site root: the entries cgi-bin/luci, cgi-bin/cgi-upload, cgi-bin/cgi-download, cgi-bin/cgi-backup and cgi-bin/cgi-exec, and a folder with a random 16-character name for the static files of the administration. A file of the site with the same name is left alone, but then the administration stops working. The rule is simple: do not name your CGI scripts like those of the router.

Ports and addresses

  • Only the HTTPS port is open from the Internet (443 by default, changeable in LuCI). Port 80 is reachable from the local network only, and there is no redirect from HTTP to HTTPS. Make the links inside the site relative or start them with /.
  • The certificate is issued for the domain chosen in LuCI. Opening the site by IP address or another name makes the browser complain about the certificate; that is expected.
  • The login page of the administration, if the site has one, is /cgi-bin/login. The administration itself is /cgi-bin/luci/.

Caching

uhttpd serves static files with ETag and Last-Modified headers and browsers cache them as they see fit. If the backend rebuilds the pages, forbid caching in index.html and change the version in the address of the styles and scripts on every build:

<meta http-equiv="Cache-Control" content="no-cache, must-revalidate, max-age=0">
<link rel="stylesheet" href="/style.css?v=1760000000">

A placeholder until the first build

If index.html is generated by the backend, still put a simple placeholder index.html into the archive: the router shows it from the upload until the first build finishes (the build starts right after the upload and usually takes seconds).

<!doctype html><html lang="en"><head><meta charset="utf-8">
<title>Loading</title><link rel="stylesheet" href="/style.css"></head>
<body><h1>The page is being built</h1><p>Come back in a minute.</p></body></html>

Example: a "members" link and a "login required" dialog

A common pattern for a site with its own login page: section links open a "sign in to continue" dialog, while the button in the header goes straight to /cgi-bin/login. Plain JavaScript, no libraries.

<a class="login" href="/cgi-bin/login">Members</a>
<a class="gate" href="/cgi-bin/login">Members-only section</a>

<div class="modal" id="auth" hidden>
  <p>This section is available after signing in.</p>
  <a href="/cgi-bin/login">Sign in</a> <button type="button" id="auth-close">Close</button>
</div>

<script>
// links with class "gate" open the dialog instead of navigating
document.querySelectorAll('.gate').forEach(a => a.addEventListener('click', e => {
  e.preventDefault(); document.getElementById('auth').hidden = false;
}));
document.getElementById('auth-close').onclick = () => { document.getElementById('auth').hidden = true; };
</script>

What to avoid

  • Heavy frameworks and megabyte bundles: the router is small and sits on a home connection.
  • Multi-megabyte images inside the archive: the archive goes into the sysupgrade backup, which is built in RAM. Keep large images elsewhere and link to them.
  • Server-side logic in the frontend: there is no PHP or similar on the router. Everything dynamic is done by the backend ahead of time, on a schedule.
