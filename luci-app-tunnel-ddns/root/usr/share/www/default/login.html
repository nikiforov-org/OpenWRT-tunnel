A login page of your own

If the archive has an executable file cgi-bin/login, then, while this site is served, the router administration can only be entered through it. The standard LuCI form is shown nowhere, and the login page looks like part of the site, for example like a "members area".

What changes when the site has a login page

RequestAnswer of the router
/cgi-bin/luci/… without a sessionthe site's 404 page: the administration is entered only through the login page
/cgi-bin/luci/… with a valid sessionLuCI as usual
/cgi-bin/luci/admin/logoutthe session is ended, the cookie cleared, 302 to /, the front page of the site
JSON requests of LuCI's own pages without a session403 with the header that makes LuCI show "session expired"; the same request from anywhere else gets the 404 page
/ubus (direct JSON-RPC)404: switched off, otherwise passwords could be guessed past the login page. LuCI switches to its RPC path through /cgi-bin/luci by itself

The LuCI files on the router are not modified: a link to the package's gate is placed into the site's document root, and the gate decides whether a request may go on. Switching the site off, or choosing a site without a login page, puts everything back.

How the CGI works

uhttpd runs cgi-bin/login for every request to /cgi-bin/login and passes the details in environment variables: REQUEST_METHOD, CONTENT_LENGTH, QUERY_STRING, REMOTE_ADDR, HTTPS (equal to on over HTTPS). The body of a POST is read from standard input. The answer is printed to standard output: header lines, an empty line, the body.

Status: 200 OK
Content-Type: text/html; charset=utf-8
Cache-Control: no-store

<!doctype html>…

The script runs as root. ucode is the natural language for it: the package's modules are ucode too, and parsing a form and producing HTML is easier there than in shell.

The package's modules

Two modules take care of everything that is not about the look of the page.

tunnel-ddns.captcha, the picture with the code

import { create, verify } from 'tunnel-ddns.captcha';

let c = create({ language: 'en' });   // { id: '…32 hex digits…', png: '…base64 PNG…' } or null
                                      // when too many pictures are waiting for an answer
verify(c.id, typed_text);             // true when the right code was typed
  • Five characters: for en Latin capitals and digits, for ru Cyrillic capitals and digits; both alphabets leave out characters that look alike (O and 0, I and 1, and so on).
  • Every character has its own colour, a random tilt and size; the picture is bent along a wave and crossed by lines. The PNG is assembled on the router without any image library, in a fraction of a second.
  • The answer is kept on the router for three minutes and checked once: after verify(), successful or not, the picture is no longer valid. Case does not matter, and Latin/Cyrillic look-alikes (A and А, C and С…) are accepted for each other.

tunnel-ddns.login, signing in to LuCI

import { login } from 'tunnel-ddns.login';

let r = login({ username: 'root', password: '…', client: env.REMOTE_ADDR, https: env.HTTPS == 'on' });
// r = { cookie: 'sysauth_https=…; path=/cgi-bin/luci/; …' }  logged in: send it as Set-Cookie
//   | { error: 'throttled', wait: 30 }                      this address has to wait
//   | { error: 'denied' }                                   wrong user name or password
  • The session is created the way LuCI does it, so after the redirect to /cgi-bin/luci/ the browser is in the ordinary administration.
  • After three failures in a row from one address there is a pause of 30 seconds, doubling with every further failure up to 15 minutes. A successful login clears the record. All addresses together may fail at most 20 times per minute.

A complete cgi-bin/login

A page with the user name, the password and the characters of the picture. The styling is yours: link the site's stylesheet and put your own markup into show_form().

#!/usr/bin/ucode
'use strict';
// Login page of the site: a captcha, then the router credentials; a successful login opens LuCI.
import { stdin } from 'fs';
import { urldecode } from 'luci.http';
import { create as new_captcha, verify as verify_captcha } from 'tunnel-ddns.captcha';
import { login } from 'tunnel-ddns.login';

const env = getenv();
const LUCI = '/cgi-bin/luci/';

// the fields of an application/x-www-form-urlencoded body
function form_fields(text) {
	let fields = {};
	for (let pair in split(text ?? '', '&')) {
		let eq = index(pair, '=');
		if (eq > 0)
			fields[urldecode(substr(pair, 0, eq), true)] = urldecode(substr(pair, eq + 1), true);
	}
	return fields;
}

function escape_html(text) {
	return replace(replace(replace(replace(text ?? '', '&', '&amp;'), '<', '&lt;'), '>', '&gt;'), '"', '&quot;');
}

function respond(status, headers, body) {
	print(`Status: ${status}\r\n`);
	for (let header in headers)
		print(`${header}\r\n`);
	print('Cache-Control: no-store\r\n\r\n', body);
}

// the form; `error` is shown above it, `username` is kept from the previous attempt
function show_form(error, username) {
	let captcha = new_captcha({ language: 'en' });
	let picture = captcha
		? `<img src="data:image/png;base64,${captcha.png}" width="200" height="60" alt="">`
		: '<span>try again in a minute</span>';
	respond('200 OK', [ 'Content-Type: text/html; charset=utf-8' ], `<!doctype html>
<html lang="en"><head><meta charset="utf-8"><meta name="viewport" content="width=device-width, initial-scale=1">
<meta name="robots" content="noindex, nofollow"><title>Sign in</title><link rel="stylesheet" href="/style.css"></head>
<body><form method="post" action="/cgi-bin/login" autocomplete="off">
<h1>Sign in</h1>
${error ? `<p class="error">${error}</p>` : ''}
<label>User name <input name="username" value="${escape_html(username)}" autofocus></label>
<label>Password <input name="password" type="password"></label>
<label>Characters of the picture ${picture} <input name="code" autocomplete="off" autocapitalize="characters"></label>
<input type="hidden" name="code_id" value="${captcha ? captcha.id : ''}">
<button type="submit">Sign in</button>
</form></body></html>
`);
}

if (env.REQUEST_METHOD == 'POST') {
	let size = +env.CONTENT_LENGTH || 0;
	let form = form_fields(size > 0 ? stdin.read(size) : '');
	if (!verify_captcha(form.code_id, form.code))
		show_form('The characters do not match the picture.', form.username);
	else {
		let result = login({ username: form.username, password: form.password,
		                     client: env.REMOTE_ADDR, https: env.HTTPS == 'on' });
		if (result.cookie)
			respond('302 Found', [ `Set-Cookie: ${result.cookie}`, `Location: ${LUCI}` ], '');
		else if (result.error == 'throttled')
			show_form(`Too many attempts. Wait ${result.wait} seconds.`, form.username);
		else
			show_form('Wrong user name or password.', form.username);
	}
}
else
	show_form('', '');

Security

Set a root password (System → Administration in LuCI). Without one, rpcd accepts any password, and neither the login page nor the captcha nor the delays can help.
  • Open the site over HTTPS only: the password travels in the form, and over HTTPS the session cookie gets the secure flag. The package does not open port 80 from the Internet.
  • Never print passwords or codes into the log or onto the page. The login module writes only the user name and the client address to the system log.
  • The CGI runs as root, like everything in uhttpd. Do not pull code you do not trust into it.
  • The login page is only the door to the administration. It cannot protect sections of the site itself: the site is static, and all its files are available to anyone.
  • Keep the page anonymous: neutral field names, no mention of the software behind it in the markup, scripts or error texts. The package does its part: while a site with a login page is served, LuCI's static files are linked under a random name, directory listings are off, and a request to an administration address without a session gets the site's 404 page, exactly like any other missing address.
