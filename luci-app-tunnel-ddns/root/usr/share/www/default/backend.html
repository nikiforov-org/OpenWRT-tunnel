Backend: pages built on a schedule

The backend here is not a server answering requests but a script that assembles static pages every now and then: it downloads news feeds, exchange rates, the weather, anything at all, and writes a finished index.html. Visitors get the file that is already built, so even a small router copes with any load.

The contract

The archive carries a .tunnel-ddns/ directory with an executable file build and whatever it needs next to it: templates, configuration, helper scripts. On upload the router moves this directory out of the web root, to /etc/tunnel-ddns/sites/<name>/, and runs build from there.

VariableValue
SITE_NAMEthe name of the site, as in LuCI
SITE_PUBLICthe document root, /usr/share/www/<name>: write the pages here
SITE_TMPa scratch directory, /tmp/tunnel-ddns/sites/<name>: a cache kept between runs, lost on reboot
  • The current directory is the script's own, so ./feeds.conf and ucode render.uc work without paths.
  • Everything the script prints goes into the log of the last build: the Rebuild log button in LuCI.
  • Exit code 0 means a successful build, anything else a failed one; the result shows in the Content line of the Overview section.
  • At most one build of a site runs at a time; a second start while one is running is silently skipped.
  • The script runs as root. Upload only your own archives.

When it runs

  • Right after the upload, so that the placeholder gives way to the real page.
  • On the Rebuild now button.
  • On the schedule from the Rebuild schedule field: five cron fields — minute, hour, day of month, month, day of week. 0 3 * * * is every night at 03:00, 0 */6 * * * every six hours, */30 * * * * every half hour. An empty field means only on the button.

A build is not started by Save & Apply or by a reboot: the built pages are on disk and stay there.

Rules of a good build

  1. Write the page to a temporary file in the same directory and swap it in with a single mv: a visitor never sees a half-written file.
  2. If the sources are unreachable, leave the old page alone and exit with a non-zero code: LuCI shows "last rebuild failed" and the site stays as it was.
  3. Download with timeouts (wget -T 25) and keep the last good copy of every source in $SITE_TMP: one failing source then does not break the page.
  4. Do not write anything into your .tunnel-ddns/ directory that need not be kept forever, and do not write to /tmp directly: that is what $SITE_TMP is for.
  5. Stay within seconds. Dozens of sources and a few hundred kilobytes are fine; parsing gigabytes on a router is not.

Example 1: rates and weather from JSON

Two files in .tunnel-ddns/: build downloads the data and calls the renderer, render.uc builds the page from the template index.ut. The shortest complete example.

.tunnel-ddns/build:

#!/bin/sh
# Downloads the data and renders index.html. Run by the router in this directory with
# SITE_PUBLIC (document root) and SITE_TMP (scratch directory, kept between runs).
PATH=/usr/sbin:/usr/bin:/sbin:/bin
: "${SITE_PUBLIC:?}" "${SITE_TMP:?}"

fetch() {   # fetch NAME URL: keeps the previous copy when the download fails
	name=$1; url=$2
	if wget -q -T 25 -O "${SITE_TMP:?}/$name.new" "$url"; then
		mv "${SITE_TMP:?}/$name.new" "${SITE_TMP:?}/$name"; echo "fetched $name"
	else
		rm -f "${SITE_TMP:?}/$name.new"; echo "could not fetch $name, using the previous copy"
	fi
}
fetch rates.json   https://example.org/api/rates.json
fetch weather.json https://example.org/api/weather.json

page="${SITE_PUBLIC:?}/.index.html.new"
DATA_DIR="$SITE_TMP" ucode render.uc > "$page" || { rm -f "$page"; echo "render failed"; exit 1; }
mv "$page" "$SITE_PUBLIC/index.html"
echo "index.html updated, $(wc -c < "$SITE_PUBLIC/index.html") bytes"

.tunnel-ddns/render.uc:

#!/usr/bin/ucode
'use strict';
// Reads the downloaded JSON files and prints index.html rendered from index.ut.
import { readfile } from 'fs';

const DATA_DIR = getenv('DATA_DIR') ?? '.';
const load = (name) => json(readfile(`${DATA_DIR}/${name}`) ?? 'null');

let rates = load('rates.json');       // whatever the API returns, e.g. { "usd": 92.5 }
let weather = load('weather.json');
if (!rates || !weather)
	die('no data yet');                 // non-zero exit: the build fails, the old page stays

let now = localtime();
print(render('index.ut', {
	rates, weather,
	built_at: sprintf('%02d.%02d.%d %02d:%02d', now.mday, now.mon, now.year, now.hour, now.min),
	escape: (s) => replace(replace(replace(s ?? '', '&', '&amp;'), '<', '&lt;'), '>', '&gt;')
}));

.tunnel-ddns/index.ut, the template: ordinary HTML where {{ }} inserts a value and {% %} holds code:

<!doctype html>
<html lang="en"><head><meta charset="utf-8"><title>Summary</title>
<link rel="stylesheet" href="/style.css?v={{ time() }}"></head>
<body>
<h1>Summary as of {{ built_at }}</h1>
<p>Dollar: {{ rates.usd }}. Outside: {{ weather.temp }}°, {{ escape(weather.text) }}.</p>
<ul>
{% for (let day in weather.forecast) { %}
  <li>{{ escape(day.date) }}: {{ day.min }}…{{ day.max }}°</li>
{% } %}
</ul>
</body></html>

Pass everything that came from outside through escape(): the template escapes nothing by itself.

Example 2: a feed from RSS

RSS is XML and ucode has no XML parser, but cutting the text up is enough for feeds. An entry is everything between <item> and </item>, the fields inside are between their own tags. Entities such as &amp; and &#8212; have to be decoded and the HTML inside the description stripped.

// the text between the first `from` and the `to` that follows it, or ''
function between(text, from, to) {
	let start = index(text, from);
	if (start < 0) return '';
	let rest = substr(text, start + length(from));
	let end = index(rest, to);
	return end < 0 ? '' : substr(rest, 0, end);
}

function clean(text) {
	text = replace(replace(text ?? '', '<![CDATA[', ''), ']]>', '');
	text = replace(text, /<[^>]*>/g, '');                 // strip tags
	text = replace(text, /&#([0-9]+);/g, (m, code) => chr(int(code)));  // ASCII only; encode UTF-8 for higher code points
	text = replace(text, '&amp;', '&');
	return trim(text);
}

let items = [];
let xml = readfile(`${DATA_DIR}/news.xml`) ?? '';
for (let chunk in slice(split(xml, '<item>'), 1)) {
	let item = split(chunk, '</item>')[0];
	push(items, {
		title: clean(between(item, '<title>', '</title>')),
		link: clean(between(item, '<link>', '</link>')),
		summary: clean(between(item, '<description>', '</description>')),
		date: between(item, '<pubDate>', '</pubDate>')
	});
}

Then the same render('index.ut', { items, … }). Several feeds: a loop over a list of addresses in your own feeds.conf. Sorting by date: turn pubDate into a number and sort(items, (a, b) => b.key - a.key).

A bandwidth test endpoint

The site ships a small CGI, cgi-bin/speed, that answers GET /cgi-bin/speed?bytes=N with N zero bytes (default 5 000 000, at most 20 000 000) taken straight from /dev/zero: nothing is stored and nothing is read from disk, so it costs no space on the router. It exists to measure the throughput of a path to this server from wherever the request is made: a tunnel client checking its connection, a monitoring script, a one-off test from a terminal:

curl -o /dev/null -w '%{speed_download}\n' 'https://example.com/cgi-bin/speed?bytes=5000000'

The endpoint needs no login and answers anyone, up to the cap per request; remove the file from the archive if the site should not offer it. A site of your own gets the same by copying the file into its cgi-bin/ (it must be executable).

Debugging

  • Rebuild log in LuCI holds the whole output of the last build; print there what you fetched and how much you wrote.
  • The Content line of the Overview: "rebuilding now", "last rebuilt 5 minutes ago", "last rebuild failed", and whether the schedule is in effect.
  • Over ssh: /usr/libexec/tunnel-ddns/sitebuild <name> starts a build by hand, ucode -c -o /dev/null file.uc checks the syntax, logread -e tunnel-ddns shows how the settings were applied.
  • To fix the script without re-uploading, you may edit the files right in /etc/tunnel-ddns/sites/<name>/, but the archive is the source of truth: the next upload overwrites everything.
