Archive and upload

The archive

  • Only .tar.gz. index.html must be at the top level of the archive or inside a single top-level folder; in the latter case the router takes the contents of that folder.
  • .tunnel-ddns/build and cgi-bin/* are made executable by the router; the modes in the archive do not matter. Everything else is served as it is.
  • Paths with .. and absolute paths fail the check.
  • On macOS tar adds ._* and .DS_Store files; they are harmless but better left out.

A packing script to keep next to the site's sources:

#!/bin/sh
# Packs src/ into dist/site.tar.gz, the archive to upload in LuCI.
set -eu
HERE="$(cd "$(dirname "$0")" && pwd)"
mkdir -p "$HERE/dist"
COPYFILE_DISABLE=1 tar -C "$HERE/src" --exclude='.DS_Store' --exclude='._*' -czf "$HERE/dist/site.tar.gz" .
tar -tzf "$HERE/dist/site.tar.gz"

Uploading in LuCI

  1. Tunnel → Dynamic DNS, section Web site, button Upload a site archive….
  2. The site name is suggested from the archive name: lowercase Latin letters, digits, dots, dashes and underscores, at most 32 characters. The name default belongs to this page.
  3. If a site with that name exists, LuCI asks whether to replace it. A replacement takes effect at once, even for the site being served: the links of the administration are restored and the build, if there is one, starts.
  4. Choose the site in the Site field and the domain in the Domain field, tick Serve the web site and click Save & Apply.

The HTTPS port is changed with the separate Change… button next to HTTPS port: it applies at once, without Save & Apply, because the web server moves to the other port together with the administration.

What the package changes on the router while a site is served

WhereWhat
/etc/config/uhttpdhome — the site's document root, cert and key — the domain's certificate, listen_https — the port, no_dirlists — on, error_page — the site's 404.html if it has one; for a site with a login page ubus_prefix is removed as well
/etc/config/luciresourcebase and mediaurlbase point at the random-named link to the static files
/etc/config/firewallthe rule tunnel_ddns_https: TCP to the HTTPS port from WAN
/etc/crontabs/rootthe line of the build schedule (and the certificate renewal line, as long as there is a certificate)
the site's document rootlinks cgi-bin/luci and cgi-bin/cgi-* to the LuCI files (or to the package's gate when the site has a login page) and a random-named link to the static files

The original uhttpd values are saved in /etc/tunnel-ddns/uhttpd.backup and restored when the site is switched off (the Serve the web site box or the Switch everything off button). Under /www only the random-named link to the static files is added while a site is served; nothing else there is changed.

Where the files are

PathContents
/usr/share/www/<name>/the public files of the site, the document root
/etc/tunnel-ddns/sites/<name>/the .tunnel-ddns/ directory of the archive: the build script and what it needs
/tmp/tunnel-ddns/sites/<name>/SITE_TMP of the build script
/tmp/tunnel-ddns/site-<name>.log, .statethe log and the result of the last build
/usr/share/www/default/this page, shipped with the package

/usr/share/www/ and /etc/tunnel-ddns/ are part of the sysupgrade backup, so uploaded sites survive a firmware upgrade. The backup is built in RAM: keep an eye on the size of the sites, shown in LuCI.

Updating and deleting

  • A new version of a site: upload an archive with the same name and confirm the replacement.
  • Deleting: the Delete button in the list of sites. Deleting the site being served switches the router to this built-in page.
  • Small fixes can be made over ssh right in the files on the router, but the next upload overwrites them: keep the source in the archive.
